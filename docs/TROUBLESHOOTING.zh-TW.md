# 疑難排解

[文件目錄](index.md) · [安裝與升級](INSTALL.zh-TW.md) · [日常操作](USAGE.zh-TW.md)

先確認使用的是本 fork 的 `0.2.0-rc.56-tw-portrait`。原作者的其他版本、Source code ZIP，以及電腦端的語音程式，是不同檔案與用途。

## USB 與燒錄

| 現象 | 先檢查 | 接著做 |
| --- | --- | --- |
| 沒有序列埠 | USB 線是否能傳資料、Hub 是否正常、裝置是否供電 | 換直連 USB 埠與資料線，再列出序列埠 |
| 序列埠忙碌 | 序列監看器、IDE 或另一個燒錄程式是否占用 | 關閉已確認占用的視窗，再重試；不要批量結束無關程序 |
| esptool 偵測到不同晶片或 Flash 大小 | 是否接到另一塊板子 | 停止寫入，先核對硬體 |
| 高速讀寫失敗 | 線材、Hub、埠號是否穩定 | 將 `--baud 460800` 改成 `--baud 115200`，保留其他參數 |
| 分割區表與建置結果不符 | 原韌體是否使用其他佈局 | 停止只更新應用程式的流程，先備份並核對移轉方案 |
| 寫入後無法啟動 | 寫入位址、鏡像種類與硬體是否正確 | 保存錯誤日誌；若有這台裝置的完整備份，依[回復流程](INSTALL.zh-TW.md#從自己的完整備份回復)處理 |

USB 偵測成功只代表電腦能與晶片通訊，不代表所選韌體適用。完整鏡像寫入 `0x0`，應用程式鏡像寫入 `0x10000`，兩者不能互換。

## 連不上 Wi-Fi 或設定頁

1. 路由器需提供裝置能使用的 2.4 GHz Wi-Fi；5 GHz-only 網路不能直接給裝置使用。
2. 設定時，手機要連接**裝置畫面顯示的熱點**，再開啟 `http://192.168.4.1`。不要把路由器分配給裝置的 IP 與設定熱點 IP 混用。
3. 手機若自動離開「沒有網際網路」的熱點，選擇繼續連線後再試。
4. 輸入密碼時注意空白與大小寫；裝置熱點與家中 Wi-Fi 不是同一個網路。
5. 儲存完成後，手機切回一般網路；裝置使用已保存的路由器 Wi-Fi，日常功能不必保持在設定熱點。

在公司、訪客、飯店網路上，即使名稱相同，也可能有用戶端隔離。隨身語音需要電腦與裝置能互通，能連上網際網路不能單獨證明這件事。

## 電臺沒有聲音

| 畫面／現象 | 判讀與處理 |
| --- | --- |
| 等待網路／網路未連線 | 先確認路由器 Wi-Fi 已連上並能連外 |
| 連線中 | 正在連到電臺；先等待，不連續快速切臺 |
| 緩衝中 | 網路已收到資料，但尚在填入播放緩衝；檢查 Wi-Fi 品質 |
| 播放失敗／重連 | 換另一臺測試；若只有特定臺失敗，可能是來源網址、伺服器或格式改變 |
| 已暫停 | 短按確定恢復播放 |
| 顯示播放中但聽不到 | 檢查系統音量，收音機與系統共用同一音量；也確認沒有停留在靜音狀態 |
| 失敗後自己跳臺 | 連續連線失敗時的播放器行為；固定清單仍會保留 |

此版十臺皆有實機解碼紀錄，但電臺來源可能日後改版或中斷。臺北廣播電臺的音訊變體約 323 kbit/s，舊版 192 kbit/s 上限會拒絕它；本版已調整為 384 kbit/s。警廣採用官方伺服器的 HTTP 1935 入口，避開曾在此裝置上實測遇到的 HTTPS 音訊片段 TLS 錯誤。

如果清單仍是中國大陸六臺、或開啟後被城市搜尋覆蓋，請核對實際燒錄版本。這兩種行為不符合本 fork 的固定十臺設定。

## 頭像與個人資料

### 換成彩色模式仍是單色

舊頭像在先前上傳時已被轉成四階亮度，頁面會停用無法還原的彩色選項，請重新選擇原始彩色照片。若是本版保存的彩色照片，直接選「彩色」並完成儲存即可還原原色，不必重新上傳。只切換主題、只選檔而沒有儲存，或圖片本身就是單色，都不會得到原始彩色效果。

### 色彩、細節與原圖不同

裝置保存 96 × 138 像素的索引色頭像，最多 255 色加透明背景。這是記憶體與畫面尺寸下的設計，不是原圖無損顯示。先把臉部放大到合適範圍，查看預覽，再調整明暗。去除背景可能移除相近色區域；不需要時取消該選項。

### 圖片上傳失敗

保持連接裝置熱點，嘗試較小的 JPEG 或 PNG，使用頁面提供的備用檔案選擇器。已有名片很多時，可先移除不需要的圖片並儲存，再重新新增。失敗上傳不應直接切換現用頭像的檔案指標；本版有雙檔案提交與錯誤回復測試。

### 簽名被截短或出現方框

長簽名在首頁可能以省略號顯示，但完整內容仍可能已保存；回到設定頁核對。方框或缺字則可能是字型子集不含該字。這版使用繁中字型子集，沒有承諾涵蓋所有罕用字、emoji 或其他語言；回報缺字時提供實際字元即可，不必附私人完整簽名。

## 語音與電腦連線

### 「隨身語音」一直等待電腦

- 開啟的是「隨身 AI 語音」，電腦也已啟動[對應轉發器](https://github.com/manchunx7-bit/folo-ai-passport-voice)。
- 電腦與裝置在可互通區域網路，UDP 33333 沒有被其他程式占用或被防火牆攔截。
- Mac 需要 BlackHole 2ch 與對應的輔助功能授權；Windows 依轉發器文件設定 VB-CABLE。
- USB 供電不會讓這個 Wi-Fi 語音功能自動變成 USB 麥克風。

### 語音面板會開，但沒有文字

核對轉發器音訊出口、輸入法的麥克風來源，以及實際語音快捷鍵。Mac 的轉發器出口與輸入法音源均為 BlackHole 2ch；系統一般輸出仍保留喇叭或耳機。先用實體鍵盤確認輸入法本身可出字，再接入裝置測試。`hold` 與 `tap` 的設定也要相符。

### 小智或 Muse 無法對話

先檢查 Wi-Fi 與帳號／服務設定。畫面能開啟不代表帳號已啟用；本儲存庫不提供共用帳號或 Token。小智電腦 MCP 控制還需要後台接入點與另外執行的電腦工具，不能只靠隨身語音轉發器。

## 系統設定與資料保留

「恢復預設」只恢復音量、亮度、熄屏、主題及按鍵音效，保留 Wi-Fi 與個人資料。若目的是換頭像或改網路，直接使用設定頁，不需要整片清除。

整片 Flash 清除與回復完整備份是另一種操作，可能覆蓋所有資料。發生問題時先保留當下備份與錯誤，再決定是否回復；不要把重新刷機當成每個問題的第一步。

## 回報問題時提供什麼

請提供：韌體版本、硬體型號、操作步驟、具體畫面訊息，以及是否只有某個電臺或功能失敗。開發者可附上已移除個人資訊的短日誌片段。

不要公開完整 Flash／NVS 備份、帳號 Token、Wi-Fi 密碼、個人照片或原始完整日誌。記錄驗證結果時，區分「程式測試通過」「實機解碼成功」與「人耳聽音／實際說話出字」。
